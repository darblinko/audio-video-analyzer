audio-video-analyzer

Records audio or video in the browser, extracts spectral, temporal and energy features with librosa, and, when a Gemini API key is set, asks a Gemini model to describe the video with those features as context. Five bundled synthetic clips run the full flow with no key, microphone or camera.

Problem

A short recording carries two kinds of information: signal properties that can be computed deterministically (pitch content, tempo, energy over time) and visual content that needs a vision model. This project computes the first locally and passes it to the second as context, so the model description and the measured features appear in one result.

The earlier version of the code converted every recording to MP3 in the browser and uploaded only the audio, so the video description step was never reached. This version uploads the original video next to a browser-encoded WAV.

Privacy: the app records the microphone and, in video mode, the camera. With GOOGLE_API_KEY set, video recordings are uploaded to the Gemini Files API. Without a key, nothing leaves the machine.

How it works

The browser decodes each recording with the Web Audio API and encodes 16-bit mono WAV, so the server needs no ffmpeg. FastAPI runs the analysis as a background task with librosa and the Gemini client in worker threads, stores the result in SQLite and pushes progress to the React client over WebSocket.

  rec["Browser recording"] --> wav["WAV encode in browser"]
  wav --> api["FastAPI upload"]
  rec -- "video mode" --> api

  api --> feat["librosa features"]
  feat --> key{"Key set and video?"}
  key -- yes --> gem["Gemini Files API and generate_content"]
  key -- no --> skip["Step recorded as skipped"]
  gem --> db[("SQLite")]
  skip --> db
  db --> ws["WebSocket to React UI"]

Measured results

Features computed on the five bundled clips: a 440 Hz sine, an A major chord, a 120 BPM click track, white noise and a speech-like signal built from harmonics shaped by vowel formants. Each clip is 5 s at 22,050 Hz, generated with seed 20261030. Only the tone and the click track have a generated reference value.

Source: results/sample-features.json at 6e3ab56. Reproduce: uv run python scripts/export_landing.py

Run it

Demo mode needs Python 3.12 with uv and Node.js 20.19 or later. It needs no API key, microphone or camera.

  1. git clone https://github.com/darblinko/audio-video-analyzer
cd audio-video-analyzer
  2. uv sync
uv run av-analyzer
  3. cd frontend
npm ci
npm run dev
  4. Open http://localhost:5173 and select Analyze on a sample clip.
  5. For video description, copy .env.example to .env, set GOOGLE_API_KEY and restart the server.

Tests: uv run pytest -q runs 49 offline tests with a stub in place of Gemini.

Limitations

  • The clip tags are fixed-threshold heuristics. On the sample clips the click track is tagged speech_or_noise and low_energy, the tone and chord are tagged slow_tempo with 0 BPM, and white noise is assigned 152.0 BPM and tagged fast_tempo.
  • librosa HPSS soft masks give white noise a harmonic share of 50.7% and a percussive share of 50.7%; the shares do not sum to 100%.
  • No recorded speech or music was evaluated. Accuracy is measured on one tone and one click track.
  • The Gemini step was tested only against a stub. The default model ID gemini-3.5-flash was not checked against Google's model list; GEMINI_MODEL overrides it.
  • The first analysis on a new install took about 20 s while numba compiled librosa's kernels; a later run in a fresh clone whose test run had already compiled them completed in under 2 s.
  • Local use only: no authentication, one SQLite file, one process. Exercised in Chromium only.
